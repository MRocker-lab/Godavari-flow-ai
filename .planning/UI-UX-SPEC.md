# GODAVARI FLOW AI — MASTER UI/UX DESIGN REQUIREMENTS

## NON-NEGOTIABLE DESIGN STANDARD

UI and UX quality are top priorities. Do not compromise visual quality, usability, accessibility, consistency or interaction quality to finish features faster.

The platform must look and feel like a professionally designed, production-grade mobility technology product, not a college project, generic admin template or AI-generated dashboard.

Design two independent experiences under one consistent GODAVARI FLOW AI brand.

---

# 1. GLOBAL DESIGN PHILOSOPHY

Apply these principles across the entire platform:

- Premium visual identity.
- Clear information hierarchy.
- Simple navigation.
- Excellent typography.
- Consistent spacing and alignment.
- Beautiful but restrained animations.
- Meaningful icons.
- High-quality maps and visualizations.
- Clear loading, empty, success and error states.
- Responsive design.
- Accessibility-first interactions.
- No unnecessary visual clutter.
- No oversized collections of identical cards.
- No excessive gradients, glassmorphism or decorative effects.
- No tiny text or low-contrast labels.
- No horizontal overflow on mobile.

Every page must have a deliberate design, not simply repeat the same dashboard layout.

Use a consistent spacing scale, typography system, color tokens, icon family, border radius system and component library.

Create reusable design-system components before implementing individual pages.

# 2. PILGRIM PORTAL — PREMIUM TRAVEL EXPERIENCE

## Design direction

The Pilgrim Portal should feel like a combination of a premium travel application, modern navigation platform and intelligent digital tourism guide.

It must be welcoming, calm, trustworthy, simple and visually beautiful.

It must NOT look like a police dashboard or an administrative application.

### Visual identity

- Warm ivory and clean white backgrounds.
- Deep royal blue for primary actions.
- River-inspired cyan and teal accents.
- Subtle saffron accents.
- Dark navy text.
- Soft shadows and carefully layered surfaces.
- Beautiful destination photography.
- Generous whitespace.
- Rounded but not excessively rounded cards.

### Homepage experience

Create a visually impressive landing page featuring:

1. A premium navigation header.
2. GODAVARI FLOW AI logo and branding.
3. Explore, Plan Journey, Parking, Shuttles and AI Assistant navigation.
4. Prominent language selector.
5. Beautiful Godavari riverfront hero image.
6. Main headline: "Discover Godavari. Experience Pushkaralu Smarter."
7. Two prominent actions: Plan My Journey and Explore Destinations.
8. AI Travel Assistant entry point.
9. Compact mobility status section.
10. Featured destination cards.
11. Smart travel information.
12. Safety and accessibility information.
13. Well-designed footer.

Do not overload the homepage with every feature. Show the most useful information first and organize the rest through navigation.

### Navigation and usability

Desktop:
- Clean top navigation.
- Clear active states.
- Logical grouping.
- Easy access to primary actions.

Mobile:
- Compact header.
- Bottom navigation for important destinations.
- Touch-friendly controls.
- Map and list views.
- No tiny menus.
- No desktop layout simply squeezed into a mobile screen.

### Journey Planner

Make this one of the best-designed features.

Use a clear guided flow:

Step 1: Select starting location.  
Step 2: Select destination.  
Step 3: Select travel mode.  
Step 4: Set family/group and accessibility preferences.  
Step 5: Compare journey options.

Present results with:

- Route map.
- Estimated journey duration.
- Walking distance.
- Traffic condition.
- Crowd level.
- Parking recommendations.
- Shuttle options.
- Reason for recommendation.

Use comparison layouts that help visitors make decisions quickly.

### AI Travel Assistant

Create a polished conversational interface.

Include:
- Clear chat messages.
- Natural language input.
- Suggested questions.
- Destination recommendations.
- Interactive map-linked responses.
- Helpful loading indicators.
- Conversation history.
- Language-aware responses.

The assistant should feel like a travel concierge, not a technical chatbot.

### Parking and shuttle experiences

Use map-first interfaces with an optional list view.

Each parking result should clearly show:
- Name.
- Available capacity.
- Occupancy.
- Distance to destination.
- Traffic condition.
- Walking distance.
- Recommendation.

Each shuttle result should show:
- Route.
- Pickup point.
- Destination.
- Estimated arrival.
- Occupancy.
- Available capacity.

Make important information immediately understandable using text, icons and status indicators, not color alone.

### Accessibility

Support:
- Large readable text.
- High contrast.
- Keyboard navigation.
- Screen-reader labels.
- Large touch targets.
- Clear Telugu and Hindi typography.
- Senior citizen mode.
- Reduced-motion preferences.

# 3. AUTHORITY COMMAND CENTRE — PROFESSIONAL OPERATIONS EXPERIENCE

## Design direction

The Command Centre must feel like a professional city mobility operations platform used by traffic police, emergency coordinators and event authorities.

Think of a modern urban mobility control room, not a generic CRM or analytics dashboard.

### Visual identity

- Deep midnight navy.
- Graphite and dark slate panels.
- Carefully controlled cyan accents.
- Red, amber and green for operational status.
- High-contrast text.
- Clean data visualizations.
- Precise typography.
- Professional technical appearance.

Use dark mode as the primary interface.

Avoid excessive neon effects, glowing borders and decorative animations.

### Command Centre main layout

Use a structured operational layout:

1. Collapsible left navigation.
2. Top command header.
3. Event/simulation mode indicator.
4. Global search.
5. Notifications and alerts.
6. Authority profile and role.
7. Central operational workspace.
8. Context-sensitive right-side information panel when appropriate.

The main workspace should prioritize the map and operational intelligence.

### Command Overview

Create a high-quality command dashboard with:

- Traffic congestion index.
- Total monitored vehicle count.
- Parking availability.
- Shuttle fleet status.
- Crowd density.
- Active incidents.
- Critical alerts.
- Predictive risk indicators.

Below the primary indicators, show:

- Large interactive mobility map.
- Crowd heatmap.
- Traffic hotspots.
- Parking locations.
- Shuttle positions.
- Incident markers.
- Recent alerts.
- AI-generated situation summary.
- Recommended authority actions.

Do not make every metric a separate giant card. Use a balanced information layout.

### Operational map

The map must be a central interactive element.

Support:
- Traffic layer.
- Parking layer.
- Shuttle layer.
- Crowd heatmap.
- Incident layer.
- Emergency routes.
- Road closure overlays.

Provide:
- Layer controls.
- Search.
- Zoom.
- Marker selection.
- Detailed location panels.
- Clear legends.
- Map/list alternatives where useful.

### AI Decision Centre

Present AI recommendations as actionable operational intelligence.

Every recommendation must include:

- Severity.
- Affected location.
- Detected condition.
- Predicted consequences.
- Recommended action.
- Reasoning.
- Expected impact.
- Approve, reject and simulate actions.

Use clear confirmation dialogs for consequential actions.

### Incident Management

Design a professional incident-management workflow with:

- Incident creation.
- Priority.
- Category.
- Location.
- Assigned response team.
- Status.
- Timeline.
- Notes.
- Resolution.

Use a clear status lifecycle such as New, Assigned, Responding, Resolved and Closed.

### Police Team Management

Show:
- Team identifier.
- Assigned location.
- Team leader.
- Assignment.
- Current task status.
- Incident association.

Use simulated assignments and clearly label them.

### Digital Twin

Make the simulator visually compelling and easy to operate.

Use:
- Scenario selection.
- Adjustable simulation controls.
- Baseline and intervention comparison.
- Map-based changes.
- Before/after charts.
- Predicted consequences.
- Reset scenario control.

Users must understand what changed and why.

### Information density

Authorities need detailed information, but the interface must remain readable.

Use:
- Progressive disclosure.
- Expandable detail panels.
- Well-designed tables.
- Search and filters.
- Sortable columns.
- Clear status chips.
- Useful tooltips.
- Consistent date/time formatting.

Never sacrifice readability to fit more information on the screen.

# 4. DESIGN SYSTEM AND COMPONENT QUALITY

Build a unified design system with separate theme tokens for both portals.

Required reusable components:

- Navigation bars.
- Sidebars.
- Buttons.
- Form fields.
- Search boxes.
- Dropdowns.
- Dialogs.
- Drawers.
- Tooltips.
- Notification panels.
- Status indicators.
- Metric visualizations.
- Data tables.
- Map controls.
- Empty states.
- Loading skeletons.
- Error states.
- Confirmation screens.
- Responsive navigation.

All components must have consistent hover, focus, disabled, active and loading states.

Use a consistent professional icon family. Do not mix unrelated icon styles or use emojis as interface icons.

Use meaningful charts with clear labels and legends.

---

# 5. MOTION AND MICRO-INTERACTIONS

Use restrained, purposeful motion.

Examples:
- Smooth page transitions.
- Subtle card hover states.
- Navigation transitions.
- Animated counters where useful.
- Map marker updates.
- Smooth notification appearance.
- Loading skeletons.
- Expand/collapse transitions.
- Clear confirmation feedback.

Animations must not delay important actions or distract users.

Respect reduced-motion preferences.

---

# 6. RESPONSIVE DESIGN

Test and optimize at:

- 360px mobile width.
- 390px mobile width.
- 768px tablet width.
- 1024px laptop width.
- 1440px desktop width.
- 1920px large desktop width.

Pilgrim Portal must be mobile-first.

Command Centre must be desktop-first but remain usable on tablets and mobile devices.

Do not simply shrink desktop dashboards on mobile. Reorganize content intelligently.

---

# 7. UX QUALITY ASSURANCE

Before declaring the platform complete, conduct a UI/UX review.

Check:

1. Can a first-time pilgrim find the journey planner without assistance?
2. Can a senior citizen understand parking and shuttle information?
3. Can users switch languages without layout breaking?
4. Can an authority identify critical alerts immediately?
5. Can a traffic officer locate a road and simulate a diversion quickly?
6. Can a command-centre operator understand the Digital Twin?
7. Are forms simple and understandable?
8. Are important actions easy to find?
9. Are errors explained clearly?
10. Are all buttons functional?
11. Does the interface work on mobile?
12. Is the information readable under real operational conditions?

Perform a separate visual review of every major page.

Do not accept a page merely because it renders successfully.

# 8. FINAL DESIGN ACCEPTANCE CRITERIA

The finished product must satisfy all of the following:

- Both interfaces look like professionally designed commercial software.
- Pilgrim Portal feels like a premium travel application.
- Command Centre feels like a professional operations platform.
- Both interfaces have distinct visual identities.
- Both are simple to navigate.
- No generic template appearance.
- No broken layouts.
- No inconsistent spacing or typography.
- No dead buttons.
- No unreadable charts.
- No misleading status indicators.
- All critical workflows are usable without technical knowledge.

**Priority order: Usability → Information clarity → Visual quality → Functional completeness → Decorative effects.**

Do not use a generic AI dashboard template. Design the complete product intentionally, page by page.
